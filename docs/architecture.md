# SPI Master Architecture

## Overview

The SPI Master Controller is designed using a modular architecture where each functional block performs a specific task during an SPI transaction.

The design supports all four SPI modes through configurable CPOL and CPHA inputs while maintaining a single FSM-based controller.

---

## Top-Level Architecture

The SPI Master consists of the following hardware blocks:

- Clock Divider
- Edge Detector
- CPOL/CPHA Logic
- FSM Controller
- Transmit Shift Register
- Receive Shift Register
- Output Logic



---

# Clock Divider

The SPI clock is generated by dividing the system clock using a programmable divider.

This allows the SPI bus frequency to be adjusted without modifying the RTL.

Responsibilities:

- Divide system clock
- Generate SCLK
- Reset divider outside the TRANSFER state

---

# Edge Detector

Instead of directly using the SPI clock, the controller detects:

- Rising edge
- Falling edge

These signals are then translated into:

- First edge
- Second edge

depending on CPOL.

This abstraction allows the same RTL to support all SPI modes.

---

# CPOL/CPHA Logic

The CPOL and CPHA inputs determine:

- Idle clock level
- Shift edge
- Sample edge

The controller computes two internal signals:

- `shift_edge`
- `sample_edge`

Every data movement inside the SPI controller is synchronized using these signals.

---

# Transmit Shift Register

The transmit register stores the data provided by the user.

Operation:

1. Loaded during LOAD state.
2. Outputs MSB on MOSI.
3. Shifts left after every shift edge.
4. Completes after DATA_WIDTH bits.

---

# Receive Shift Register

Incoming MISO data is captured into the receive shift register.

Operation:

1. Cleared in LOAD state.
2. Samples MISO on each sample edge.
3. Shifts one bit every sample.
4. Updates `rx_data` after the final sample.

---

# FSM Controller

The controller operates using four states:

- IDLE
- LOAD
- TRANSFER
- DONE

The FSM coordinates every operation performed by the SPI master.

Its responsibilities include:

- Starting transfers
- Controlling chip select
- Managing busy/done signals
- Ending transfers after all bits have been sampled

---

# Output Logic

The output logic drives:

- MOSI
- Chip Select
- Busy
- Done
- SPI Clock

These outputs depend entirely on the current FSM state.

---

# Design Highlights

- Parameterized data width
- Parameterized SPI clock
- Full-duplex communication
- Supports all SPI modes
- Synthesizable RTL
- Single FSM architecture
- Portable SystemVerilog implementation
